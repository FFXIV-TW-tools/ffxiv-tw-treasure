### 批次 1：worker 路由授權破口（預期 1 commit ＋ **deploy STOP** · 驗證 `node worker/tests/worker.test.mjs` ＋ `cd worker && pnpm cf:deploy:dry`）

#### 1-1 `POST /room/:code` 不得整份覆蓋房間清單（B-006 · medium · 本輪唯一線上實證項）
- **動機**：無 `Origin`、空 body 的 `POST /room/<房號>` 現在回 200 並清空全隊清單、重設 6h 期限、且不廣播（線上實證於自建測試房）。這是唯一繞過 op-based 模型與 `confirmModal` 的路徑。
- **檔案**：`worker/src/index.js:160-162`（default fetch 轉發）、`:212-223`（`Room.fetch` POST 分支）
- **做法**（goal-driven：先寫重現測試 → 修 → 轉綠）：
  1. 先在 `worker/tests/worker.test.mjs` 加失敗測試：抽一個純函式 `publicRouteAllowed(method, parts)`（或 `seedPathAllowed(pathname)`），斷言 `POST /room/ABCDEF` → 拒、`GET /room/ABCDEF` → 准、WS 升級 → 准、內部 `https://do/seed` → 准。
  2. default fetch：`/room/:code` 只轉發 GET 與 WS 升級，其餘 method 回 404/405。
  3. `Room.fetch` 的 POST 分支加內部路徑守衛：`new URL(req.url).pathname === '/seed'` 才接受（內部呼叫用的正是 `https://do/seed`），否則 405。**兩層都做**（縱深防禦：任一層將來被改動仍有另一層）。
  4. 導出的必須是 function（`worker/src/index.js:270` 的鐵則，B-004 踩過）。
- **驗證**：`node worker/tests/worker.test.mjs` 全綠且 assert 數上升 → 同步更新 `AGENTS.md:45` 基線與 0-1 的 `expect`；`pnpm -C worker cf:deploy:dry` 0 error；deploy 後用建測試房重跑本輪的實證命令，應回 405/404 且 `GET` 顯示點還在。
- **依賴**：批次 0-1（基線數字要一起改）。
- **STOP**：`worker/` 改動需 **Owner 手動 `pnpm -C worker cf:deploy`**，不由 agent 執行。deploy 前後都要跑上面的驗證。

> 同批可順手（同檔、同一次 deploy，避免為 low 項再開一次 STOP 流程）：DO 對可解釋的拒絕回 `{t:'error', reason:'room_full'|'rate_limited'|'unknown_op'}`（client `opError` 分支已存在）、`st == null` 併入 expired 路徑、`order` 補 no-op 收斂、`normalizePoint` 的 `ownerName` 去控制字元。**是否納入由 Owner 決定**——納入可省一次 deploy 窗，但會擴大單次 commit 的 scope。

## 執行備註

- **commit 顆粒度**：按批次切，一批一主題；批次 2 的文件項可合併成 1-2 個 commit（`docs:` scope），別與程式改動混在一起。繁中 Conventional Commits、不加 Co-Authored-By。
- **push ＝ STOP**：本 repo 獨立 `.git`，push 走 cmd.exe 由 shawn 自跑（`external/*` 有註冊 canonicalTest，可走 `safe-push.sh --repo <絕對路徑>`）。
- **worker deploy ＝ STOP**：批次 1 完成後必須 `pnpm -C worker cf:deploy:dry` 0 error，正式 `cf:deploy` 由 shawn 執行。deploy 後回寫 `CHANGELOG` 的 Verified 與 `_INDEX` 狀態（本輪報告已指出這行三週內 stale 過兩次）。
- **部署順序**：批次 1 若納入「DO 回 error reason」，屬 client 可向下相容的新增（舊 client 收到未知 `t` 會忽略），前端後上無妨；反之若日後動 `applyOp` 的既有 op 語意，一律 worker 先行。
- **基線只准升**：任何批次加了 assert 就同步更新 `AGENTS.md:45` 與批次 0-B 對應那支的 `expect` 值（四個 tag 各自獨立）；下降必須在 CHANGELOG 寫明理由並經複審。
